## Module vidéo (`fm_video/`)

Demande de l'utilisateur (octobre 2026, cahier des charges « PIPE FMZ — module vidéo et image professionnel ») : lecteur de vidéos (appareil photo, production) et de séquences d'images (EXR, TIFF, DPX, PNG, JPEG…) DANS l'appli, navigation EXACTE image par image dans les deux sens, image TOUJOURS centrée, informations en surimpression (I), colorimétrie OCIO + corrections non destructives, LUT .cube, export, conversion de cadence. Troisième PAQUET (comme `board/`, `fm_markdown/`) ; aucune dépendance vers la fenêtre principale (elle pose `fm_video.pane.HOOKS` : réglages, `save_state`, `resolve_color` = `app_style.resolve_color_ref`, `resolve_font`, `status`). Dépendances (optionnelles, `requirements.txt`, installées par le .bat) : PyAV (FFmpeg intégré : décodage), OpenImageIO (EXR / TIFF / DPX, précision d'origine), OpenColorIO (config ACES intégrée `ocio://cg-config-latest` par défaut), PyOpenGL (affichage GPU) ; export par le FFmpeg du PATH (`FFMPEG_EXECUTABLE`), RIFE = `rife-ncnn-vulkan` (réglage `video_rife_path`, sinon `$RIFE_NCNN_VULKAN`, PATH, puis le binaire officiel téléchargé dans `tools/rife/` — ignoré par git — ; modèle v4 le plus récent passé en chemin ABSOLU, `export.rife_model` : seuls les modèles v4 acceptent un nombre d'images quelconque `-n`, et le modèle par défaut est cherché dans le dossier courant) ; LibVLC = VLC 3 installé (64 bits) + `python-vlc` (lecture, voir MOTEURS).

sources `VideoSource` / `ImageSource` : `read(rang) -> Frame` type d'origine uint8 / uint16 / float16 / float32, JAMAIS réduit à 8 bits ; vidéo : rang -> horodatage RÉEL par l'index des paquets `build_index` (fond, cadence variable comprise), saut à l'image clé d'avant puis décodage jusqu'à l'image — jamais une approximation en secondes ; vidéo = 1 fil, reculer garde les images décodées les plus proches (`extra_window`) ; séquence = N fils) ; `color` (pipeline documenté en tête du fichier : LUT technique « source » -> espace d'entrée OCIO -> travail = rôle `scene_linear` -> corrections -> display / view OCIO -> LUT créative « display » -> niveaux / luminosité -> canal / écrêtage -> fond ; - MOTEURS DE LECTURE (demande de l'utilisateur, octobre 2026 : « qualité et fluidité de VLC », son, réseau) : réglage `video_engine` (« vlc » par défaut, « pyav »). LibVLC (`vlc_engine.VlcPlayer`, instance unique créée en fond par `fm_video.preload`) = décodage matériel D3D11VA, sortie audio WASAPI, synchronisation audio / vidéo et caches de VLC (`:file-caching` = `video_cache_local_ms`, `:network-caching` = `video_cache_network_ms` — VLC applique le second aux fichiers d'un partage réseau) ; ses images ne vont PAS dans une fenêtre native (surimpression, coins arrondis, LUT / OCIO impossibles) mais en mémoire : callbacks « vmem » I420 posés DIRECTEMENT dans nos tampons numpy (aucune copie Python), état par tampon (libre / VLC / dernière / interface : jamais réécrit pendant son envoi au GPU), callbacks ctypes à NOUS posés par les fonctions brutes de `vlc.dll` (le `c_char_p` de python-vlc rend le chroma non inscriptible) ; JAMAIS d'appel à LibVLC depuis un callback de VLC (interblocage) : signaux Qt. PIÈGES mesurés sur VLC 3.0.21 : taille donnée = taille CODÉE (2176 lignes pour 2160, 1090 pour 1080) : on ne montre que la taille du flux ; après la fin du média, `play()` / `set_time()` sont refusés tant que le lecteur n'est pas ARRÊTÉ (cause du « plus de son à partir de la 3e lecture » : `VlcPlayer.play` fait `stop()` d'abord) ; volume posé avant la création de la sortie audio ignoré : reposé à l'événement Playing ; la 1re image après un départ / saut est un APERÇU périmé (départ à 20 : 16 puis 20…) : écartée (`_vlc_skip`) ; `get_time` avance par paliers (~150 ms) et reste un moment à l'ancienne valeur après un départ (0 en MP4) : rang = horloge de VLC interpolée (`_vlc_index`, ancre recalée au-delà de 120 ms d'écart), notre horloge depuis la 1re image tant que celle de VLC n'a pas bougé ; un saut EN PAUSE (`set_time`) remontre une image figée plusieurs fois : reprise sans déplacement = `set_pause(0)`, sinon nouveau départ `stop` + média `:start-time` (`_play_vlc`). Mesuré (images au gris connu) : rang exact à ±1 image pendant la lecture, EXACT à la pause. PyAV ne décode RIEN pendant la lecture VLC (index des images compris : `VideoSource.index_gate`, la construction attend — elle lisait tout le fichier, gros MKV / réseau) ; pause = image EXACTE du rang atteint par PyAV (`_pause_vlc`) ; pas à pas, IN / OUT, glisser sur la timeline (lecture suspendue le temps du geste : `_scrub_started` / `_scrub_finished`), export : PyAV. Boucle : `:input-repeat` (boucle coupée en cours : arrêt détecté au retour en arrière), boucle IN / OUT = saut au rang IN. Repli PyAV si VLC / python-vlc absents. Ne jamais remplacer la navigation exacte PyAV par VLC (exigence « non négociable »).
- AFFICHAGE / NETTETÉ (cause du « moins net que VLC ») : (1) mipmaps trilinéaires dès qu'on réduisait (une 1080p à 88 % mélangeait 18 % d'une version réduite de moitié) — maintenant SEULEMENT sous 50 % (`video_mipmaps`), sinon bilinéaire comme VLC, pixels exacts à 100 % ; (2) image posée à un DEMI-pixel (centrage) : chaque pixel mélangé à son voisin à 100 % — coin calé sur un pixel PHYSIQUE (`_ViewMixin.image_rect`) ; (3) conversion YUV -> RVB faite sur le CPU (swscale, puis 3 ou 6 octets par pixel envoyés) : les vidéos arrivent en planes YUV (`media.YuvImage`, vues sur la mémoire de PyAV / tampons de VLC) et le SHADER convertit (`sampleSource` : matrice Kr / Kb du fichier, plage vidéo / pleine, 8 à 12 bits, chromas recalés d'un quart de pixel quand ils sont alignés à gauche — H.264 / HEVC ; centrés pour MJPEG / MPEG-1) — même conversion pour VLC et PyAV (aucun saut de couleur à la pause ; = FFmpeg à <1,5 / 255, test) ; `Frame.pixels` (repli CPU, analyse) converti à la demande, `Frame.value_at` pour la valeur sous le curseur. Zoom initial `video_default_zoom` : « smart » (défaut : réduite si plus grande que la zone, sinon 100 % — jamais agrandie ; mode `smart` du viewer, suivi au redimensionnement), « fit », « 100 », « last » (`video_last_zoom`, état temps réel). CADRE DE L'IMAGE (Réglages > Module vidéo > Affichage : `video_frame_border_*` (Bordures, côtés + couleur + épaisseur), `video_frame_radius` (Border radius, 4 coins), Ombres `video_frame_shadow` (SHADOW_PREFIXES) + décalages X / Y et extension) : dessinés par le shader autour du rectangle VISIBLE (distance signée à un rectangle arrondi, antialiasée : vraie découpe des coins, bordure à l'extérieur, ombre floue côté par côté) — un seul passage plein écran, coût nul en lecture ; jamais exportés ; repli CPU par QPainter.

VOLUME : une seule valeur `_volume` (0-100, `video_volume`), libellé « n % » À CÔTÉ du curseur (le « 100 % » que l'utilisateur prenait pour le volume était le ZOOM, posé juste avant le bouton du son), muet à part (le volume est retrouvé en rétablissant le son), reposé à chaque média et à chaque création de sortie audio. Lecture automatique à l'ouverture (`video_autoplay`, ALLUMÉE par défaut ; coupée : 1re image en pause) : une seule demande (`play` ne fait rien si la lecture tourne). Timeline : unité Images / Secondes (liste « Images / Secondes » de la barre, `video_time_display` = « Unité de timeline par défaut », état temps réel) — affichage seulement ; secondes = temps RÉEL de chaque image (`source.time_of` / `index_at_time` : horodatages des vidéos à cadence variable, fractions exactes pour 23,976 / 29,97), graduations `Timeline._paint_seconds`, `format_seconds`. Plein écran = le module reparenté dans une fenêtre plein écran (contexte GL recréé : `initializeGL` refait tout), contrôles masqués après 2,2 s sans souris.

- SACCADES : LA VRAIE CAUSE (« ça saccade encore beaucoup », octobre 2026) — les sondes précédentes (`_probe_video_module.py`, fenêtre principale OUTILLÉE mais SANS le démarrage réel) étaient fluides parce qu'elles n'avaient pas la fenêtre de réglages préchargée : `SettingsWindowV2._prebuild_step` construit ses ~24 000 widgets SUR LE FIL DE L'INTERFACE, par étapes de 40-50 ms, dès que l'utilisateur ne touche ni souris ni clavier — c'est exactement le cas pendant qu'on REGARDE une vidéo : 1 à 2 images perdues à chaque étape (lecture réelle 1080p 25 i/s : 157 images sur 200, trou de 732 ms). - SCOPES (`fm_video/scopes.py`, touche S / bouton de la barre, état `video_scopes`) : histogramme R / V / B / luma, waveform (luma par colonne), vectorscope (Cb / Cr BT.709, repères 75 %, ligne des tons chair) calculés sur l'image TELLE QU'AFFICHÉE (`color.process_np` : corrections, LUT, OCIO) d'une version réduite (≤ 360 px de large, YUV décimé sans convertir l'image entière) dans un fil de fond (`ScopeWorker` : une demande remplace la précédente, ~6 par seconde ; tampon de VLC copié avant), ~10 ms par calcul en 4K (`np.bincount`, pas `np.add.at` : 5 fois plus lent) ; rien n'est calculé panneau caché ; panneau `ScopesPanel` posé par-dessus l'afficheur, transparent à la souris.
