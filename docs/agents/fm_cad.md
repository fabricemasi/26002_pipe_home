## Module CAD du board (`fm_cad/cad*.py`, phase 1 + arcs, cercles, polylignes, DÉCALER, CHANFREIN, RACCORD, TEXTES, DÉCOMPOSER, AJUSTER À LA AUTOCAD)

Demande de l'utilisateur (octobre 2026, cahier des charges « module CAD professionnel intégré à MRO ») : dessin technique 2D à la manière d'AutoCAD DANS la page MRO (le board), développé PAR PHASES — phase 1 faite (lignes, accrochages, calques, barre de commande) ; de la phase 2, POLYLIGNE, CERCLE, ARC (avancés pour faire les outils correctement, accord de l'utilisateur) ; de la phase 3, DÉCALER, CHANFREIN, RACCORD, ROTATION, MIROIR, ÉCHELLE, AJUSTER ; RECTANGLE ; de la phase 4, les hachures et les TEXTES (TEXTE, MTEXTE) ; de la phase 3, DÉCOMPOSER ; de la phase 5, les cotations (non associatives) ; le 2026-11-04, le reste : ELLIPSE, POLYGONE, POINT, DIVISER, MESURER (phase 2), PROLONGER, ÉTIRER, COUPURE, JOINDRE, RÉSEAU (phase 3), cotations associatives (phase 5) — voir COMMANDES DES PHASES 2 ET 3 et COTATIONS ASSOCIATIVES ; la phase 6 (optimisation) a été menée au fil des mesures (NAVIGATION DANS UN GROS DWG OUVERT, PAN FLUIDE…). Plus aucune commande « prévue ». Référence = comportement documenté d'AutoCAD (LINE, OSNAP, coordonnées, calques) ; aucun code repris.
- FICHIERS (couches, chacune n'importe que les précédentes) : `cad_geometry` (pur : conversions, projections, intersections, motifs, `GridIndex`), `cad_shapes` (pur : géométrie des entités en PRIMITIVES `("segment", a, b)` / `("arc", c, r, a0, ouverture)` — tessellation, emprise, plus proche point, intersections segment / arc / cercle, renflements, arcs par 3 points, poignées, déplacement), `cad_tools` (pur : DÉCALER, CHANFREIN, RACCORD ; une chaîne = message d'impossibilité), `cad_model` (pur : calques, entités, ByLayer), `cad_input` (pur : grammaire des saisies), `cad_snap` (pur : moteur d'accrochage), `cad_items` (`CadLineItem`, rendu), `cad_commands` (commandes + registre), `cad_overlay` (rendu temporaire), `cad` (`CadController` : point d'entrée, coordination), `cad_bars` (barres d'outils flottantes : cases et disposition), `cad_ui` (panneaux, fenêtres, menus). `model` importe `cad_model` (type `cad_line` dans `DEFAULTS`, `normalize_line`) ; `scene` importe `cad_items` (enregistre le type dans `ITEM_CLASSES`).
- INTÉGRATION NATIVE : une entité CAD = un ÉLÉMENT du board (`cad_line`) : sur la page, enregistrée dans le `.mro`, annulée (`StateCommand`), copiée / collée / dupliquée / exportée comme les autres, visible quand le mode CAD est coupé (et déplaçable / supprimable par le board). Calques et propriétés courantes dans `page["cad"]` (versionné `CAD_VERSION`, absent tant que le CAD n'a pas servi : un board sans CAD s'écrit EXACTEMENT comme avant ; changements de calques = état `__page__`, donc annulables). RÈGLE : ne jamais modifier sur place un dictionnaire de `page["cad"]` (les états d'annulation le partagent) — `cad_model.copy_cad` puis `CadController.set_cad` / `set_cad_and_items`. Champs inconnus (version plus récente) gardés : entité, extrémités, calques, `page["cad"]`.
- COORDONNÉES (jamais mélangées) : ÉCRAN (pixels du viewport : tolérances, marqueurs, poignées) ; SCÈNE (unités du board, Y vers le bas) ; DOCUMENT (mêmes unités, Y vers le HAUT, angles trigonométriques, 0 = est, comme AutoCAD) : `doc = (scène.x, -scène.y)` (`cad_geometry.to_doc` / `to_scene`, `CadController.view_to_doc` / `doc_to_view` en flottants). Géométrie en double précision, `p1` / `p2` jamais arrondis ; la place Qt d'une ligne (déplacement du board, collage) est ajoutée aux points (`CadLineItem.points`) et repliée à l'enregistrement (`to_dict` : x = y = 0).
- LIGNE (`CadLineItem`) : calque, couleur / épaisseur / type de ligne `ByLayer` ou override (résolus AU DESSIN par `cad_model.resolve`, jamais recopiés : changer le calque met à jour ses lignes ByLayer), échelle du type, extrémités `end1` / `end2` : coupe franche, arrondi (demi-cercle AU-DELÀ du point, comme la terminaison ronde), border radius 0-100 % de la demi-épaisseur (DANS la coupe ; deux extrémités trop proches : rayons réduits ensemble) — contour exact généré par `line_outline` ; épaisseur en unités du board (saisie / affichée dans l'unité de mesure), 0 (ou < 1 pixel à l'écran) = trait fin d'un pixel ; motifs (types de ligne réglables, voir TYPES DE LIGNE : unité de mesure × échelle de la page × échelle de l'entité ; trop serrés à l'écran : trait continu). Longueur / angle toujours entre les points de référence (accrochages aussi). Aucune image gardée (`NO_CACHE`, `_set_item_cache` la saute) ; contours / motifs en cache, refaits si géométrie ou propriétés changent. Calque masqué : invisible, ni accrochable ni sélectionnable ; calque verrouillé (ou verrou du board) : `locked()` vrai, ni modifié ni déplacé ni supprimé, mais ACCROCHABLE.
- COMMANDES (`cad_commands.REGISTRY`, alias anglais / français, `_` et `-` ignorés) : une seule implémentation lancée par la barre d'outils, la barre de commande ou une touche (`CadController.run`). LINE / L / LIGNE (segments indépendants ; options annUler / Clore ; Entrée au 1er point = reprise à la dernière extrémité ; Échap GARDE les segments ; UNE étape d'annulation par commande, segments ajoutés hors annulation puis `commit_created`), MOVE / M, COPY / CO (copies multiples, annUler), ERASE / E (sélection préalable ou invite « Choix des objets » : clic, fenêtre, TOUT, Entrée), poignées (`GripCommand` : clic-clic ou glisser ; ÉTIREMENT des extrémités — toutes les poignées au même point suivent —, DÉPLACEMENT par le milieu, Entrée = mode suivant, option Copier), LAYER / LA, PROPERTIES / PR (Ctrl+1), OSNAP / OS / DS, U, REDO, ORTHO, POLAR, GRID, SNAP, HELP / AIDE, CADQUIT. Commande prévue tapée = message « prévue en phase N » ; Entrée / Espace à « Commande : » = répéter la dernière.
- SAISIE (`cad_input.parse`) : `x,y` absolu (barre de commande ; RELATIF en saisie dynamique pour un point suivant, `#x,y` absolu), `@dx,dy`, `@d<a`, `d<a`, `@` seul, distance directe (direction de l'élastique : ORTHO / polaire / suivi compris), `<a` = angle imposé, `END` / `MID` / `PER`… = accrochage ponctuel (`NON` = aucun), options par leurs capitales. Séparateur décimal = le POINT, toujours (« 12,5 » est un point) ; saisie non reconnue = message, jamais de géométrie devinée. Saisie dynamique (F12) : champs près du curseur (X / Y, ou distance / angle), Tab verrouille la valeur tapée et passe au champ suivant.
- MAJ = ORTHO INVERSÉ (demande de l'utilisateur, comme AutoCAD) : tant que Maj est enfoncée pendant une invite de point AVEC point de base (LIGNE, POLYLIGNE, DÉPLACER…), ORTHO est inversé (contraint aux axes si coupé, libre s'il est actif ; coupe aussi le polaire), le réglage n'est pas touché (`SnapEngine.resolve(ortho_toggle=)`). Appui / relâchement de Maj refont l'aperçu tout de suite (`CadController._shift_refresh`, état FORCÉ : les modificateurs de l'appli ne sont pas à jour pendant l'événement de la touche). - ARCS, CERCLES, POLYLIGNES (octobre 2026) : types `cad_arc` (center, radius, start, end : sens trigonométrique, comme le DXF), `cad_circle` (center, radius), `cad_pline` (vertices [[x, y, renflement]], closed — renflement = LWPOLYLINE du DXF) ; mêmes propriétés que la ligne (`cad_model.PROP_DEFAULTS`, `ENTITY_DEFAULTS`, `normalize_entity`, `new_entity_values`). - CLICS PERDUS (signalé : « environ un clic sur deux est ignoré ») — cause PROUVÉE par de vrais clics Windows (SendInput) journalisés : quand deux clics sont rapides et proches, Qt REMPLACE le 2e appui par un événement de DOUBLE-CLIC (séquence reçue : appui, relâche, DOUBLE, relâche — jamais de 2e appui) ; `mouse_double_click` ne traitait le double-clic comme un appui qu'à une invite de POINT : ailleurs (2e coin d'une fenêtre de sélection, 2e objet à « Choix des objets », 2e clic de sélection) il était jeté, et sa relâche aussi faute d'appui. Correction : un double-clic compte TOUJOURS comme un appui (`mouse_press(log=False)`) ; hors commande, sur un objet, sa relâche choisit le plus proche (pas de cycle entre objets superposés) et ouvre ses propriétés (`_press_double`) ; seuil clic / glisser `CLICK_PX` = 4 px. Journal désactivable des événements souris : `PIPELINE_CAD_MOUSE_LOG=1` (`_log_mouse` : sorte, position, invite, fenêtre en attente, commande). Autre fin de commande corrigée au passage : une commande à choix immédiat qui se termine dans `picked` (chanfrein, raccord) était laissée active (`_select` appelle maintenant `_after_step`). Tests `FastClicksTest` (séquence de Qt reproduite).
- RÉTICULE PENDANT UN PAN (demande de l'utilisateur) : il reste SOUS le pointeur — mode CAD, le curseur de la vue reste le réticule même pendant un déplacement (`BoardView._sync_cursor` délègue à `cad._sync_cursor`) ; chaque pas de pan donne la position écran au contrôleur AVANT le défilement (`cad.cursor_view`), `_view_changed` relit le point du document, l'accrochage, la saisie dynamique et les coordonnées ; défilement nul (bord) = simple mouvement (`CadController.pan_moved`). Test `test_crosshair_snap_and_coordinates_follow_a_pan`. LATENCE CURSEUR / CONTENU PENDANT UN PAN (signalé, trois captures au bouton du milieu : le dessin traîne de 50 à 80 px derrière le réticule en bougeant vite) : le curseur du système est posé par Windows tout de suite, le contenu arrive 2-3 images plus tard (peinture, vsync, composition).
