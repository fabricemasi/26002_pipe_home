# Colonnes, navigation, opérations sur les fichiers, lancement des logiciels

## Carte : fonctionnalité → fichiers

La classe `Column` et son constructeur restent dans `column.py` ; elle compose les
mixins de `column_parts/`. Les imports historiques de `column.X` restent disponibles.
Pour modifier une fonctionnalité, ouvrir directement son fichier et cette carte.

| Fonctionnalité | Fichier |

| Largeur, hauteur, lignes, événements et glisser d’entête | `column_parts/geometry.py` |
| Chargement, entrées, compteurs et affichage des lignes | `column_parts/loading.py` ; scan asynchrone dans `column_loading.py` |

### Services du navigateur (`browser_core.py`)

`browser_core.py` est la façade historique ; les services sont dans
`browser_core_parts/` et ne dépendent pas de la fenêtre principale.

| Fonctionnalité | Fichier dans `browser_core_parts/` |
|---|---|
| Scan, chemins réseau, métadonnées et cache des configurations | `scan.py` |
| Dimensions et configuration des styles de colonnes | `dimensions.py` |
| État des dossiers IN / OVER / OUT et dénombrements | `status.py` |
| Configuration des projets, dispositions, punaises et raccourcis | `project_config.py` |
| Icônes logiciels, punaises et vignettes de dossiers | `icons.py` |
| Rôles de ligne, badges et peinture des images / titres | `row_paint.py` |
| Application des réglages, indicateurs, tailles et presets | `settings.py` |
| Instantanés, capture d’écran et fantôme de déplacement | `capture.py` |
| Explorateur et dialogues des vignettes de dossier | `system_ui.py` |
| Fondus, glissements, survol et minuterie haute résolution | `animation.py` |

Les couches n’ont pas de cycle d’import : `scan` est une base, puis les services
qui l’utilisent ; `row_paint` et `dimensions` précèdent `settings`, tandis que
`capture` et `icons` précèdent `system_ui`. Les caches dictionnaires sont partagés
par référence. Les valeurs réaffectées `_CONFIG_REVISION` (`scan`) et
`_default_thumbnail` (`icons`) sont lues dynamiquement par la façade : le chargeur
`column_loading` voit immédiatement toute invalidation. Patcher le module qui
appelle : `browser_core_parts.scan` pour les fonctions réseau, `settings` pour
les lectures / écritures de presets ; les appels extérieurs directs à la façade
gardent leurs patches sur `browser_core`. Les sondes neutralisent aussi les
écritures dans `project_config` et `settings` ; `tests/_probe_isolate.py` dirige
les réglages et presets vers des copies sans modifier leur préchargement ; la
synchronisation CSS Obsidian est désactivée comme dans les tests. Les fonctions
déjà importées par les colonnes et la fenêtre sont aussi neutralisées.
La sonde de navigation compte et profile également les fichiers des nouveaux
paquets, pour ne pas masquer leurs accès réseau ou leur temps de peinture.

## `software_launch.py`

- `software_launch.py` : ouvrir un logiciel « au bon emplacement ». Dans un set, un logiciel choisi dans la colonne LOGICIELS (dossier reconnu par `software_icon_key`) qui a un lanceur (`LAUNCHERS` : BLENDER, HOUDINI — demandes de l'utilisateur, les autres « au fur et à mesure ») : TOUTES les colonnes ouvertes sous son dossier (dossier = celui du logiciel ou en dessous) ont, juste avant leur punaise, un bouton à son icône (`Column.set_launcher`, créé à la demande ; posé par `PipelineBrowser._sync_software_buttons`, appelé à chaque `add_column`) ; clic = le logiciel s'ouvre dans le dossier de la colonne (`_launch_software`). Blender : lancé (détaché, dossier courant = la colonne) avec un chemin de scène QUI N'EXISTE PAS (`untitled.blend`, puis `untitled_01.blend`… : un fichier existant serait ouvert) ; Blender ouvre la scène par défaut et retient ce chemin (« saving will write to … », vérifié sur Blender 5.2) : Enregistrer sous s'ouvre dans le dossier, rien n'est créé avant l'enregistrement ; il signale au passage qu'il n'a pas pu lire ce fichier (attendu). Le dossier est AUSSI ajouté aux favoris (« Bookmarks ») de sa fenêtre de fichiers (demande de l'utilisateur) : section `[Bookmarks]` de `bookmarks.txt`, lu par Blender au démarrage, écrit juste avant le lancement (`add_blender_bookmark` : une seule fois par dossier, reste du fichier et fins de ligne gardés, écriture par fichier temporaire), NOMMÉ D'APRÈS LE SET (demande de l'utilisateur ; nom du dossier terminal de la chaîne, `_chain_terminal_path`, passé par `_sync_software_buttons` → `launch(clé, dossier, set)`) : ligne `!<nom>` au-dessus du chemin (syntaxe de Blender, vérifiée) ; favori déjà présent = seul son nom est remis à jour. File > OPEN dans ce dossier aussi (demande de l'utilisateur) : tant que la scène n'est pas enregistrée, Blender ouvre la fenêtre d'Open dans le dossier du PREMIER fichier récent (et non dans celui de la scène, contrairement à Enregistrer sous) — la scène est donc mise en tête de `recent-files.txt` avant le lancement (`add_blender_recent` : mécanisme de Blender lui-même, valable pour le menu File, l'écran d'accueil et Ctrl+O ; scènes ajoutées par le lancement précédent et jamais enregistrées retirées, liste tenue dans `data/blender_recent_added.json`, ignoré par git ; reste de la liste et fins de ligne gardés). Essayé puis abandonné : script de démarrage `--python-expr` qui habillait les menus (marchait) et ajoutait Ctrl+O dans la configuration « addon » (ne passe pas devant le raccourci d'origine) ; piège : `bpy.data.is_saved` est VRAI dès que le chemin de la scène est posé, même sans fichier. Vérifié de bout en bout sur Blender 5.2 (configuration isolée) : Open et Enregistrer sous dans le dossier, rien d'écrit dans le dossier ; dossier `config` = `BLENDER_USER_CONFIG`, sinon `<installation>/portable/config`, sinon `%APPDATA%/Blender Foundation/Blender/<version de l'installation>/config` (`_blender_config_dir`) ; les favoris s'accumulent (Blender les retire par clic droit). Vérifié sur Blender 5.2 avec une configuration ISOLÉE (`BLENDER_USER_CONFIG`, `TEMP` vers un dossier temporaire — sinon Blender réécrit le `quit.blend` de l'utilisateur en quittant). Houdini (`_launch_houdini`) : `houdini.exe` (licence des préférences de l'utilisateur ; `HOUDINI_EXECUTABLE`, sinon le `bin` de hython) lancé SANS scène, dossier courant = la colonne : une scène sans titre a pour `$HIP` le dossier courant (vérifié sur Houdini 21 avec hython : `<dossier>/untitled.hip`), Enregistrer sous / Ouvrir s'y ouvrent, rien n'est créé. Un nouveau logiciel = une fonction dans `LAUNCHERS` (doit faire de même : « Enregistrer sous » dans le dossier). Test `tests/test_software_launch.py` (aucun logiciel lancé). Bouton « + » de l'entête de la colonne LOGICIELS (demande de l'utilisateur) : menu des logiciels de Réglages > ICONES > Logiciels (`browser_core.software_choices` : ceux d'origine moins les retirés, puis les ajoutés ; ceux qui ont déjà leur dossier grisés), le choix crée son dossier en minuscules (« houdini ») dans le dossier listé par la colonne et le sélectionne (`Column._open_software_menu` / `_create_software_folder`) ; test `tests/test_software_menu.py`.

### Animations des colonnes
- Overlays dans `browser_core.py` : `_FadeOverlay` (fondu d'un instantané, avec `retarget`/`finish_now`) et `_SlideOverlay` (repli/dépli glissant des colonnes du projet) ; `_fine_timer` (timer Windows haute résolution) et `_HoverPrime` (pré-chauffe au survol).
- Re-clic sur la ligne DÉJÀ sélectionnée d'une colonne (`FileListWidget.mouseReleaseEvent` → `PipelineBrowser.on_reclicked`) : elle est désélectionnée (la colonne perd son focus) et toutes les colonnes ouvertes après elle se referment en fondu, inspecteur vidé ; dans IN/OVER/OUT/LOGICIELS, seul le contenu ouvert depuis le groupe se ferme. Sonde : `tests/_probe_reclick.py`.
- Orchestration dans `PipelineBrowser` (`pipeline_browser.py`) : `_set_columns_hidden` / `_apply_project_columns_collapsed` (masquage et repli, animés ou non), `_animate_column_in` (apparition par dessous, fondu échelonné), `_fade_before_select` (fondu de l'ancien contenu à la sélection).
- Principe : on anime un **instantané** (`grab`) plutôt que les vrais widgets ; les instantanés sont pré-calculés (`_prewarm_snapshots`, `_prime_*`) et validés (`_snapshot_blank`, `_fade_snapshot_fresh`). L'état final réel est toujours posé par `*_now` / `finish_now` : toute nouvelle animation doit finir par là pour ne pas laisser l'UI dans un état intermédiaire.
- Retour des colonnes depuis la visionneuse SANS À-COUP (saccade signalée, mesure à l'écran `tests/_probe_viewer_exit_frames.py`, `FOLDER=<vrai dossier> STEPS=6 WAIT=…` ; ~180 ms de blocage au clic avant correction) : (1) sélectionner OU DÉSÉLECTIONNER un FICHIER ne reconstruit plus la pile d'aperçus (colonnes Focus, groupe IN/OVER/OUT/LOGICIELS, ~100 ms) si la chaîne des dossiers et l'habillage n'ont pas changé (`update_preview_stack(if_changed=True)`, `_preview_stack_key`) ; (2) la capture des colonnes pour leur retour est faite D'AVANCE, au repos dans la visionneuse, 900 ms après la synchro de la colonne (`_return_grab` → `_pregrab_columns` : colonnes affichées, capturées, re-masquées sans retour à la boucle ; reportée si une animation tourne), avec la place de retour de l'image dans l'inspecteur (`snapshot[6]`, appliquée au retour par `_retarget_focus_source(relevee)` — jamais pendant la visionneuse : elle peut changer l'image du centre) ; le retour démarre en ~3 ms ; revenir moins d'une seconde après avoir changé d'image refait la synchro et la capture au clic (~80 ms) ; (2 bis) planche ouverte, au repos : la colonne est DÉSÉLECTIONNÉE d'avance (sa sortie vers les colonnes ne laisse aucun fichier sélectionné ; colonnes masquées, rien ne se voit, `_gallery_deselected`, `_deselect_viewer_file`) puis capturée : la sortie depuis la planche démarre aussitôt (avant ~180 ms, puis ~90) ; revenir de la planche à une IMAGE la resélectionne (`_close_focus_gallery` → `_viewer_sync`) ; sonde `tests/_probe_gallery_back_to_image.py` ; (3) avant toute capture, les mises en page en attente sont faites (`_settle_columns_layout` : un widget caché ne se remet pas en page — capture et place de retour étaient relevées sur l'ancienne mise en page de l'inspecteur, l'image arrivait 50 à 80 px à côté et sautait à la fin).

- Performance du dessin des colonnes (chaque clic déclenche des captures = repeintures complètes) : la vignette FINALE d'une ligne est mise en cache (`browser_core._ROW_IMAGE_CACHE`, clé = `pixmap.cacheKey()` + taille physique + rayon ; la recalculer à chaque peinture coûtait ~40 % d'une repeinture) ; les contrôles de fraîcheur faits en peignant (icônes perso, vignettes de dossier, date des fichiers) passent par `previews.cached_mtime` (1,5 s) et ce que l'appli écrit elle-même appelle `forget_mtime`. Ne pas remettre de calcul d'image ni de `stat` dans un `paint`. Mesure : `repaint()` de `scroll.viewport()` sous cProfile. Sondes sans `app.exec()` : appeler `QCoreApplication.sendPostedEvents(None, QEvent.DeferredDelete)`, sinon les `deleteLater()` ne s'exécutent jamais et on croit voir une fuite.
- Tester « une animation est en cours » avec `_anim_running(overlay)` (pipeline_browser.py), jamais `overlay.running` seul (un overlay détruit sans finir garderait `running` vrai et bloquerait tout). Les fins d'overlay (`_finish`/`_complete`) sont en try/finally : l'overlay disparaît même si un rappel lève une erreur. Un clic pendant un glissement le termine (`finish_now`) au lieu d'abandonner le fondu. Stress : `tests/_probe_anim_stress.py` (clics rapides, repli, masquage ; vérifie qu'aucun overlay ne reste et compte les fondus sautés).
- À surveiller : un `retarget` ou un clic pendant une animation doit terminer/rediriger l'overlay en cours (sinon colonnes fantômes) ; instantané obsolète ou vide après changement de réglages/taille (re-prime) ; `_install_qt_message_filter` masque certains avertissements Qt, à vérifier si un vrai message disparaît.
- Fenêtres natives : `main()` pose `AA_DontCreateNativeWidgetSiblings`. Sans lui, le `winId()` d'une fenêtre enfant (`apply_dwm_frame` des réglages) rendait `#CentralFrame` natif et les animations ne s'affichaient plus qu'en une image. Ne jamais appeler `winId()` sur un widget non fenêtre. Mesure de ce qui s'affiche réellement à l'écran : `tests/_probe_screen_anim.py` (compte les images par repli/dépli, réglages fermés/ouverts).
- `files/parametres rendus.txt` : le chemin HDRI pointe maintenant vers `F:\SYNC\Sync\IMAGES\hdri\` (chemin propre à la machine, à adapter ailleurs).

## Barre de navigation : boutons de mode

Demande de l'utilisateur : à la suite du repli des colonnes, bouton VISIONNEUSE (`btn_viewer`, kind `"viewer"`, icône `navbar_viewer`) = visionneuse sur la sélection la plus profonde (`_selected_path` : fichier à aperçu tel quel, dossier = sa 1re photo, autre fichier = les photos de son dossier) ; visionneuse ouverte = retour aux colonnes (`_on_viewer_button`). Puis bouton ÉDITEUR (module Markdown / code, `btn_text_editor`, kind `"text_editor"`, icône `navbar_text_editor`), GRISÉ tant que la sélection n'est pas un fichier texte / de code (`fm_markdown.is_text_file` : `fm_markdown.TEXT_EXTENSIONS` ; `_sync_mode_buttons`, appelé à chaque sélection / désélection et par `_sync_collapse_button`). Bouton d'un mode ouvert = fond accent à 35 % (`_mode_on_color`).

## Opérations sur les fichiers (confirmations)

Demande de l'utilisateur : toute suppression et tout glisser d'éléments dans un autre dossier passent par une fenêtre de confirmation, `settings_dialogs.confirm(parent, étiquette, titre, message, éléments, action)` (briques des réglages : en-tête du sélecteur de couleur, rôles de texte, barre du bas des réglages ; Entrée = confirmer, Échap / croix = annuler ; 8 éléments nommés au plus). Toute nouvelle opération destructrice ou de déplacement doit l'utiliser.
- « Supprimer » (menu d'une ligne, sauf raccourci ; menu de la vignette Focus d'un dossier) : `Column.delete_path` → CORBEILLE (`QFile.moveToTrash`) ; corbeille refusée (disque réseau) → 2e confirmation « supprimer DÉFINITIVEMENT ». Ligne ouverte : refermée d'abord comme un re-clic (`on_reclicked`).
- Glisser-déposer (`FileListWidget.dropEvent`) : la confirmation s'ouvre APRÈS le dépôt (`confirm_drop`, hors de l'opération de glisser du système) et la source apprend toujours une COPIE — depuis l'explorateur Windows en « déplacer », c'est lui qui effacerait les originaux, même après une annulation ; le déplacement est fait par l'appli une fois confirmé (`apply_drop`, sans confirmation, testable). Rien à faire (déjà dans ce dossier…) : pas de fenêtre (`drop_sources`).
- Glisser d'une colonne à l'autre (SEUL déplacement sans Ctrl) : la LIGNE en curseur, à `DRAG_GHOST_OPACITY`, tenue où on l'a prise (`FileListWidget.drag_pixmap`, `setHotSpot`) ; dans la colonne survolée, aperçu EN DIRECT de l'emplacement (`_DropPreview`, indicateur de Qt coupé) : dossier visé en surbrillance (l'élément ira dedans), sinon UN SEUL emplacement, celui qu'il occupera (`predicted_row` : tri de `Column.refresh`, dossiers puis fichiers par nom, après l'ordre choisi à la main, jamais après les lignes du bas) ; rien quand le dépôt ne ferait rien (`drop_sources`, gardé par dossier visé pendant le glisser). Le dépôt suit le même dossier que l'aperçu (`_drop_target`).
