## `markdown_preview.py`

- `markdown_preview.py` : rendu Markdown -> HTML PARTAGÉ par le mode lecture du module Markdown et l'aperçu des notes de l'inspecteur (`render_body`, `render_fragment`, `render_page`), lecture / écriture FIDÈLES (`read_note` / `write_note` : encodage dont cp1252, BOM, fins de ligne, fichier temporaire puis remplacement ; `changed_on_disk`). Conversion markdown-it-py + mdit-py-plugins + syntaxe des notes de l'utilisateur écrites dans Obsidian ([[liens|alias]], ![[image.png|300]], callouts, `==…==`, `#tags`, URL nues, `%%…%%`, propriétés en tableau). Images / liens relatifs résolus depuis la note (sous-dossiers compris), puis PAR NOM dans la racine de la note (`note_root` : coffre = parent avec `.obsidian`, sinon le dossier de la note ; `file_index`, parcouru en fond, 30 000 fichiers au plus, gardé 30 s) ; les références du texte ne sont jamais modifiées. AUCUN style ici : `render_page` (inspecteur) prend `mdeditor/web/base.css` + les variables de l'onglet Markdown (`mdeditor/style.py`) — même rendu que le module ; CodeMirror (coloration des blocs de code) chargé seulement si la note en a. Plus aucune lecture de l'installation d'Obsidian (l'ancien `obsidian.asar` / `app.css` / snippets du coffre). Piège : le document doit défiler par `html`, jamais par `body` (un `body` en `overflow:auto` tombe à 0 px de haut et découpe toute la note). Autre piège : une `QWebEngineView` placée sous un `QGraphicsEffect` (les coins arrondis de la carte, `_RoundedCornersEffect`) reste FIGÉE à l'écran sur sa première image : la vue de l'inspecteur est enfant direct du `DetailPanel`, posée sur sa place `markdown_slot` (`_place_markdown_view`), jamais dans la carte. ÉDITION depuis l'inspecteur : bouton « Modifier / Lecture » ou Ctrl+E, éditeur texte source (`markdown_editor`), enregistrement automatique 800 ms après la frappe, conflit = « Garder ma version / Recharger le fichier / Annuler » (`_save_markdown`) ; test `tests/test_markdown_edit.py`. « Ouvrir dans l'application Obsidian » (clic droit d'une note d'un coffre, ou double-clic avec Markdown > Ouverture > « Double-clic sur une note » = Application Obsidian) : `obsidian_open_url` → `obsidian://open?path=<chemin absolu>` ; coffre = un parent avec `.obsidian` ou un coffre déclaré dans `%APPDATA%/obsidian/obsidian.json` (`vault_containing`) ; test `OpenInObsidianTest`. QtWebEngine ne dessine pas en offscreen : sondes visuelles en affichage natif, fenêtre hors écran. Test `tests/test_markdown_preview.py`.

- DÉFILEMENT (refonte d'octobre 2026, demande de l'utilisateur : « comme un éditeur classique », sans saut) : UN scroller natif par mode, sans aucune interception de la molette (seul Ctrl + molette des fichiers de code, écouté sur `#md-edit`). HAUTEURS INDÉPENDANTES DU DÉFILEMENT : `LivePreview` décore tout le document (passage de fond `sweepSlice` en tranches de 5 ms sur `requestIdleCallback`, suspendu 200 ms après un défilement / redimensionnement, éditeur caché = en pause, `resume`) : 0. tous les blocs (callouts, tableaux) d'abord, 1. estimations, 2. lignes (état exact du mode, tokenisation avancée par paquets de 250 lignes — un appel lointain rejouait des milliers de lignes, 50 ms) ; rien n'est retiré quand une ligne sort de l'écran ; les lignes que CodeMirror affiche sont décorées DANS son `viewportChange` (même tâche, avant la peinture : `refreshNow`), avec la VRAIE position du scroller (`visibleRange` — pendant un saut, CodeMirror annonce la zone avant de mettre à jour la sienne). Toute décoration passe par `mutate` : la ligne en haut de la vue garde sa place (recalage DANS l'opération, CodeMirror rend directement au bon endroit) ; une estimation changée hors de CodeMirror force son rendu (`curOp.forceUpdate`). ESTIMATIONS (`Editor.estimateLine`, `lineShape`, `rememberHeights`, `settleEstimate`) : hauteur mesurée gardée par ligne tant que texte / largeur / style (`layoutKey`) n'ont pas changé ; sinon modèle appris par genre (titres, lignes vides, code, bords de bloc de code, texte : rangée + rangée repliée ; blocs rendus par nombre de lignes, comptés comme rendus même pas encore décorés, `blockAt`) ; images : dimensions lues par Python dans leur ENTÊTE (`op_imageSizes`, `QImageReader`, en fond) → hauteur calculée (largeur max des images mesurée dans la page) et place réservée (`width` / `height`, posés aussi sur les images déjà dessinées, `imageSizeArrived`). Mesure (note de la sonde) : hauteur estimée à ~0,2 % près (17 % avant). Bascule lecture → édition : `Editor.shown` (`setSize`, jamais `refresh`, qui jetait toutes les hauteurs mesurées). Redimensionnement : la ligne du haut est relevée au 1er `resize` et reposée au `refresh` de CodeMirror (100 ms après).
