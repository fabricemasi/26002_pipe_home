# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Projet

Pipeline Browser : navigateur de fichiers en colonnes (Miller columns) en PySide6, pour une arborescence de projets de production (racine par défaut `F:\PIPELINE`, réglable via `root_path` dans `data/pipeline_settings.json`). Application Windows (DPI per-monitor, attributs « caché » Windows, chemins `.exe`) ; le code et les commentaires sont en français. Le dépôt est édité depuis WSL mais l'appli tourne sous Windows.

## Commandes

- Lancer : `pipeline_browser_debug.bat` (crée `.venv`, installe PySide6/ezdxf/matplotlib, lance l'appli) ou `python pipeline_browser.py` (`pythonw` pour éviter la console).
- Dépendances : `requirements.txt` (PySide6 ; optionnels : OpenEXR, numpy, ezdxf, matplotlib).
- Tests (unittest, offscreen Qt, certains exigent Blender installé) :
  - tous : `python -m unittest discover -s tests`
  - un fichier : `python -m unittest discover -s tests -p test_turntable.py`
  - un test : `python -m unittest tests.test_render_log.RenderLogTest.test_requested_columns_and_render_metadata` (lancer depuis la racine ; les tests importent `previews`, `detail_panel`… : patcher un nom dans le module qui l'utilise, pas dans celui qui l'a importé).
- Tout fichier de test commence par `import _isolate` (`tests/_isolate.py` : réglages, presets et état des fenêtres redirigés vers des COPIES temporaires). OBLIGATOIRE pour tout nouveau test : `SaveTest` enregistrait et `update_active_preset` écrivait dans le VRAI fichier de presets — le preset « fab » de l'utilisateur a reçu les valeurs du test (curseurs 20 / 9), rejouées ensuite par-dessus ses réglages (« les sliders changent de style tout seuls », signalé). Doubler des fonctions de presets : les remplacer dans `settings_store` (là où `update_active_preset` les cherche), pas seulement dans le module testé.
- Pas de linter ni de build configuré.
- `.venv/` est ignoré par git (ne pas l'éditer).

## Architecture

Modules plats à la racine (aucun package), en couches : chaque module n'importe que ceux qui le précèdent (les imports tardifs `import browser_core as pb_core` dans `settings_*` évitent le cycle).

Application (ordre de dépendance) :
- `config.py` : constantes (extensions, listes d'omission `GLOBAL_OMIT_*`) ; `ui_state.py` : réglages d'interface **réassignés à l'exécution** (`WINDOW_RADIUS`, `HEADER_HEIGHT`, `STEP_BADGE_STYLE`…). Ils se lisent toujours via `ui_state.X` (jamais `from ui_state import X`, qui figerait la valeur).
- `previews.py` : décodeurs d'aperçus, caches mémoire/disque, rendus Blender/Maya, ordonnanceur de fond, journal de rendu.
- `browser_core.py` : scan disque, config projet/layout/raccourcis, helpers de peinture/redimensionnement.
- `row_delegates.py` (`RowDelegate`, `ProjectTileDelegate`), `column_config.py` (dialogue de configuration des colonnes), `capture_widgets.py` (capture, `_PreviewBlock`, `_ColumnCard`…), `column.py` (`Column`), `preview_column.py` (`PreviewColumn`, export PureRef), `detail_panel.py` (`DetailPanel`, inspecteur).
- `software_launch.py` : ouvrir un logiciel « au bon emplacement ». Dans un set, un logiciel choisi dans la colonne LOGICIELS (dossier reconnu par `software_icon_key`) qui a un lanceur (`LAUNCHERS` : BLENDER, HOUDINI — demandes de l'utilisateur, les autres « au fur et à mesure ») : TOUTES les colonnes ouvertes sous son dossier (dossier = celui du logiciel ou en dessous) ont, juste avant leur punaise, un bouton à son icône (`Column.set_launcher`, créé à la demande ; posé par `PipelineBrowser._sync_software_buttons`, appelé à chaque `add_column`) ; clic = le logiciel s'ouvre dans le dossier de la colonne (`_launch_software`). Blender : lancé (détaché, dossier courant = la colonne) avec un chemin de scène QUI N'EXISTE PAS (`untitled.blend`, puis `untitled_01.blend`… : un fichier existant serait ouvert) ; Blender ouvre la scène par défaut et retient ce chemin (« saving will write to … », vérifié sur Blender 5.2) : Enregistrer sous s'ouvre dans le dossier, rien n'est créé avant l'enregistrement ; il signale au passage qu'il n'a pas pu lire ce fichier (attendu). Le dossier est AUSSI ajouté aux favoris (« Bookmarks ») de sa fenêtre de fichiers (demande de l'utilisateur) : section `[Bookmarks]` de `bookmarks.txt`, lu par Blender au démarrage, écrit juste avant le lancement (`add_blender_bookmark` : une seule fois par dossier, reste du fichier et fins de ligne gardés, écriture par fichier temporaire), NOMMÉ D'APRÈS LE SET (demande de l'utilisateur ; nom du dossier terminal de la chaîne, `_chain_terminal_path`, passé par `_sync_software_buttons` → `launch(clé, dossier, set)`) : ligne `!<nom>` au-dessus du chemin (syntaxe de Blender, vérifiée) ; favori déjà présent = seul son nom est remis à jour. File > OPEN dans ce dossier aussi (demande de l'utilisateur) : tant que la scène n'est pas enregistrée, Blender ouvre la fenêtre d'Open dans le dossier du PREMIER fichier récent (et non dans celui de la scène, contrairement à Enregistrer sous) — la scène est donc mise en tête de `recent-files.txt` avant le lancement (`add_blender_recent` : mécanisme de Blender lui-même, valable pour le menu File, l'écran d'accueil et Ctrl+O ; scènes ajoutées par le lancement précédent et jamais enregistrées retirées, liste tenue dans `data/blender_recent_added.json`, ignoré par git ; reste de la liste et fins de ligne gardés). Essayé puis abandonné : script de démarrage `--python-expr` qui habillait les menus (marchait) et ajoutait Ctrl+O dans la configuration « addon » (ne passe pas devant le raccourci d'origine) ; piège : `bpy.data.is_saved` est VRAI dès que le chemin de la scène est posé, même sans fichier. Vérifié de bout en bout sur Blender 5.2 (configuration isolée) : Open et Enregistrer sous dans le dossier, rien d'écrit dans le dossier ; dossier `config` = `BLENDER_USER_CONFIG`, sinon `<installation>/portable/config`, sinon `%APPDATA%/Blender Foundation/Blender/<version de l'installation>/config` (`_blender_config_dir`) ; les favoris s'accumulent (Blender les retire par clic droit). Vérifié sur Blender 5.2 avec une configuration ISOLÉE (`BLENDER_USER_CONFIG`, `TEMP` vers un dossier temporaire — sinon Blender réécrit le `quit.blend` de l'utilisateur en quittant). Houdini (`_launch_houdini`) : `houdini.exe` (licence des préférences de l'utilisateur ; `HOUDINI_EXECUTABLE`, sinon le `bin` de hython) lancé SANS scène, dossier courant = la colonne : une scène sans titre a pour `$HIP` le dossier courant (vérifié sur Houdini 21 avec hython : `<dossier>/untitled.hip`), Enregistrer sous / Ouvrir s'y ouvrent, rien n'est créé. Un nouveau logiciel = une fonction dans `LAUNCHERS` (doit faire de même : « Enregistrer sous » dans le dossier). Test `tests/test_software_launch.py` (aucun logiciel lancé). Bouton « + » de l'entête de la colonne LOGICIELS (demande de l'utilisateur) : menu des logiciels de Réglages > ICONES > Logiciels (`browser_core.software_choices` : ceux d'origine moins les retirés, puis les ajoutés ; ceux qui ont déjà leur dossier grisés), le choix crée son dossier en minuscules (« houdini ») dans le dossier listé par la colonne et le sélectionne (`Column._open_software_menu` / `_create_software_folder`) ; test `tests/test_software_menu.py`.
- `markdown_preview.py` : notes `.md` rendues avec le CSS d'Obsidian (page HTML pour la `QWebEngineView` de l'inspecteur, `DetailPanel._show_markdown`, créée au premier `.md`, toute la hauteur de l'aperçu ; sinon repli sur l'extrait texte brut). Coffre = parent avec `.obsidian`, sinon celui ouvert dans Obsidian (`%APPDATA%/obsidian/obsidian.json`). Conversion markdown-it-py + mdit-py-plugins, syntaxe Obsidian ajoutée (liens/intégrations `[[…]]`, callouts, `==…==`, `#tags`, URL nues, `%%…%%`, propriétés) ; structure du mode lecture reproduite (`markdown-preview-view` / `el-*`) pour que les règles d'Obsidian s'appliquent. Piège : le document doit défiler par `html`, jamais par `body` (un `body` en `overflow:auto` tombe à 0 px de haut et découpe toute la note). Autre piège : une `QWebEngineView` placée sous un `QGraphicsEffect` (les coins arrondis de la carte, `_RoundedCornersEffect`) reste FIGÉE à l'écran sur sa première image (la page défile, l'affichage non ; invisible en offscreen et dans `grab()`) : la vue est enfant direct du `DetailPanel`, posée sur sa place `markdown_slot` (`_place_markdown_view`), jamais dans la carte. Vérification à l'écran : capture `PrintWindow` avec `PW_RENDERFULLCONTENT` (une capture d'écran GDI ne voit pas le contenu GPU). Mode gardé d'une note à l'autre ; même note réaffichée = éditeur intact. Test `tests/test_markdown_edit.py`. Double-clic (ou « Ouvrir ») sur une note .md d'un coffre Obsidian = Obsidian s'ouvre SUR elle (`markdown_preview.obsidian_open_url` → `obsidian://open?path=<chemin absolu>`, `PipelineBrowser.on_activated`) ; coffre = un parent avec `.obsidian` ou un coffre déclaré dans `obsidian.json` qui contient la note (`vault_containing`, sans le repli de `vault_for` sur le coffre ouvert) ; hors coffre : son logiciel ; test `OpenInObsidianTest`. - `focus.py` : état « focus » (se concentrer sur un objet : aperçu image/turntable pour l'instant, d'autres types à venir) ; `FocusOverlay` anime l'objet de l'inspecteur au centre quand on masque les colonnes. ### Animations des colonnes
- Overlays dans `browser_core.py` : `_FadeOverlay` (fondu d'un instantané, avec `retarget`/`finish_now`) et `_SlideOverlay` (repli/dépli glissant des colonnes du projet) ; `_fine_timer` (timer Windows haute résolution) et `_HoverPrime` (pré-chauffe au survol).

- Objets des lignes à contrôle (demande de l'utilisateur) : MÊMES gestes que dans les tableaux (voir « Objets libres ») — Ctrl+Maj + glisser = déplacer dans sa ligne (+ Q / Z), Ctrl+Maj+X + glisser un bord = redimensionner (aimanté aux objets de la ligne sous le curseur), Ctrl+Z dans le menu. Le moteur de `settings_cells` est générique : son HÔTE est une cellule de tableau ou tout widget qui porte `_objects_host` (ici `_MenuRow`, magasin `_MenuObjects` : `objects`, `set_object`, `commit`, `owner_window`, `snap_rows`) ; la case d'icône et l'écart d'une ligne sont marqués `_no_object`. Rejoué à chaque affichage (`_apply_objects`, appelé par `prepare_menu`), retenu dans la disposition du menu (`objects` : `{"row:<texte>|<chemin>": [x, y, l, h]}`).
- Style des TOGGLES des lignes (demande de l'utilisateur) : clic droit sur un toggle = « Style du toggle » ; retenu dans la disposition du menu (`toggles` : `{"row:<texte>|<chemin>": style}`, écouteur `_menu_toggle_listener` dans `TOGGLE_STYLE_LISTENERS`), rejoué à l'affichage. Personnalisation permise : l'éditeur du menu prend le clic droit — son menu d'édition commence alors par « Style du toggle » et le toggle n'ouvre pas le sien en plus (`_toggle_at`, drapeau `_ctx_menu_handled` lu par `_Toggle.contextMenuEvent` ; vérifié par un vrai clic droit système, sinon les deux menus s'ouvraient l'un après l'autre).
- Tests `tests/test_context_menu.py` (alignement au pixel avec / sans icônes et coches, style, disposition, glisser, édition), `tests/test_menu_objects.py`.

## Opérations sur les fichiers (confirmations)

Demande de l'utilisateur : toute suppression et tout glisser d'éléments dans un autre dossier passent par une fenêtre de confirmation, `settings_dialogs.confirm(parent, étiquette, titre, message, éléments, action)` (briques des réglages : en-tête du sélecteur de couleur, rôles de texte, barre du bas des réglages ; Entrée = confirmer, Échap / croix = annuler ; 8 éléments nommés au plus). Toute nouvelle opération destructrice ou de déplacement doit l'utiliser.
- « Supprimer » (menu d'une ligne, sauf raccourci ; menu de la vignette Focus d'un dossier) : `Column.delete_path` → CORBEILLE (`QFile.moveToTrash`) ; corbeille refusée (disque réseau) → 2e confirmation « supprimer DÉFINITIVEMENT ». Ligne ouverte : refermée d'abord comme un re-clic (`on_reclicked`).
- Glisser-déposer (`FileListWidget.dropEvent`) : la confirmation s'ouvre APRÈS le dépôt (`confirm_drop`, hors de l'opération de glisser du système) et la source apprend toujours une COPIE — depuis l'explorateur Windows en « déplacer », c'est lui qui effacerait les originaux, même après une annulation ; le déplacement est fait par l'appli une fois confirmé (`apply_drop`, sans confirmation, testable). Rien à faire (déjà dans ce dossier…) : pas de fenêtre (`drop_sources`).
- Glisser d'une colonne à l'autre (SEUL déplacement sans Ctrl) : la LIGNE en curseur, à `DRAG_GHOST_OPACITY`, tenue où on l'a prise (`FileListWidget.drag_pixmap`, `setHotSpot`) ; dans la colonne survolée, aperçu EN DIRECT de l'emplacement (`_DropPreview`, indicateur de Qt coupé) : dossier visé en surbrillance (l'élément ira dedans), sinon UN SEUL emplacement, celui qu'il occupera (`predicted_row` : tri de `Column.refresh`, dossiers puis fichiers par nom, après l'ordre choisi à la main, jamais après les lignes du bas) ; rien quand le dépôt ne ferait rien (`drop_sources`, gardé par dossier visé pendant le glisser). Le dépôt suit le même dossier que l'aperçu (`_drop_target`).
- Tests `tests/test_file_operations.py` (corbeille simulée : ne jamais appeler la vraie dans un test).

## Conventions du projet

**Styles : jamais inventés.** Tout élément qui a déjà son équivalent dans les réglages (tableau, titre, zone de saisie, toggle, panneau…), y compris dans la fenêtre principale, est construit AVEC les briques des réglages (`settings_window_v2.seed_window_look` puis `_flat_cells_table` / `build_cells_table`, rôles de texte, `_title_font`, `_PanelFrame` + `M`, `make_field`) ; précédents : `settings_quick_style.QuickStyleWindow`, `focus.FocusInfoPanel`. Demande expresse de l'utilisateur, valable pour tout élément à venir.

`over/Notes.txt` définit des **gabarits** pour les lignes de la fenêtre de réglages, à appliquer à toute ligne existante ou future du même type sans que l'utilisateur le répète :
- Lignes *police* : une seule ligne ; toggles app/système sans texte, collés au menu déroulant ; toggle « gras » avec le texte « gras » avant (les deux états) ; texte « Hauteur » avant le slider.
- Lignes *arrondi des angles* : une ligne, pas de bouton copier, toggle « lier les 4 » (texte avant, les deux états), 4 sliders avec champ de saisie, valeur mise à jour en temps réel.
- Lignes *bordures* : pas de bouton copier, toggle « lier les 4 », 4 toggles chacun au-dessus du choix de couleur de son côté.
Styles de la fenêtre de réglages — une seule source par type d'élément, jamais de style posé à la main :
- Textes : un **rôle** (`TEXT_ROLES` dans `settings_theme.py`, appliqué par `_set_text_role` / `_text_label`). Changer l'apparence d'un type de texte = modifier son rôle, pas les sites d'appel.
- Arrondis des zones de saisie et des boutons : chaque widget s'inscrit à sa création (`_register_input` / `_register_radius`) et suit le réglage tout seul. Un nouveau widget habillé en zone de saisie doit s'inscrire ; ne jamais tenir de liste de champs à mettre à jour.
- Tableaux : tous ont un entête (`_ResizableTableHeader` : sélection de colonnes Maj+clic, toggle « largeurs égales »). `_build_flat_table` / `_build_override_flat_table` ajoutent eux-mêmes l'entête Paramètre|Valeur (`_attach_flat_head`) et s'inscrivent (`_register_flat_table`) ; les tableaux à cellules (Icônes, Logiciels) passent par `_register_cells_table`. Arrondi, bordure, padding et couleur d'entête passent par `_set_flat_tables_style` / `_TABLE_HEAD`.
- Dimensions : la bordure droite de chaque `_TableFrame` est agrippable (largeur du tableau, collé à gauche au niveau du titre) ; largeur du tableau + largeurs de colonnes sont enregistrées dans `table_dims` (clé = titres des sections + rang, voir `_TableFrame.dimsKey`).
- Vérification : `tests/test_settings_window.py` (aller-retour des valeurs, suivi des styles) et `tests/_probe_compare.sh` (captures de toutes les pages avant/après, comparées au pixel ; `tests/_probe_diff.py` localise les différences).

Lire `over/Notes.txt` en entier avant de modifier la fenêtre de réglages (`over/Prompts.txt` contient l'historique des demandes).

## Commit et push

- Commit depuis WSL avec `git` (identité globale déjà configurée) ; `git add -u` pour les fichiers suivis, `lancer.sh` (non suivi) n'est pas à ajouter.
- Le push se fait avec `git.exe push` (Git for Windows, via le Gestionnaire d'identifiants Windows) : un `git push` WSL échoue (« could not read Username for 'https://github.com' »). Sinon, pousser depuis un terminal Windows dans le dossier.
- Messages de commit en français, terminés par la ligne `Co-Authored-By` demandée par l'environnement.
